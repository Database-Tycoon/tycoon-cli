Headline: **TBD**. Two streams in this one.

**Filesystem sources grow up.** Multiple named resources per source,
JSONL alongside CSV and Parquet, config that is validated instead of
quietly defaulted, and an interactive resource loop in `sources add`.
This is the first slice of the dlt-user archetype bet.

**The city stops being a static plan.** It is laid out by pipeline
depth — marts downtown, sources on the periphery — traffic and guests
are actually drawn, and coverage panels stop reporting unmeasured data
as zero. The three limitations 0.2.0 shipped with are closed.

## Landed

_Filesystem-source entries (gh-222 through gh-228, PRs #229–#235) are
written in as they merge._

- **The city is laid out by pipeline depth** (PR #206). Marts and gold
  schemas sit downtown, sources on the periphery, so the shape of the
  city now tells you where a table sits in your pipeline. Median route
  length on the dogfood catalog fell from 229 tiles to 36. Streets are
  drawn where traffic actually goes instead of everywhere, and every
  table in a schema is inside that schema's district — previously a
  table could be placed outside its own district.
- **Traffic and guests are visible.** In 0.2.0 the vehicle and guest
  simulations ran but nothing was drawn, so the counters climbed over
  an empty street. Both now render, interpolated between ticks.
- **Coverage panels report unknown instead of zero.** In 0.2.0 a
  catalog whose coverage had never been measured displayed
  `columns documented 0%`, which reads as measured-and-bad rather than
  unmeasured. The inspector, problems gauges, and library tour now say
  unknown when that is what the data says.
- **`R` refreshes the whole view.** The footer, legend, and notes kept
  the previous city's values after a refresh.

### For contributors

- **The renderer is covered by CI.** The vendored `tests/tycoon_city`
  suite (563 tests, including the `city.json` contract golden) joins
  the default `pytest` run instead of being excluded, and
  `src/tycoon_city` counts toward coverage (floor 68 → 73). A new `web`
  job runs `tsc`, the production build, a check that the shipped
  `web_dist/` matches a fresh build of `web/`, and the Playwright e2e
  suite. In 0.2.0 the CLI was gated and the renderer was not.

## Upgrading from 0.2.0

- **`tycoon.yml`'s `schema_version` stays at `2`** — there is no
  migration to run.
- **Filesystem sources sharing a schema now land in their own tables.**
  Projects with data already in the old generic `read_csv` /
  `read_parquet` table get a one-time warning naming both the stale
  table and the new one. New rows go to the new table only, so a dbt
  model still selecting the old name needs updating by hand.
- **The city looks different.** The radial layout reorders precincts by
  pipeline depth, so a city rendered from the same catalog will not
  match a 0.2.0 screenshot. The `city.json` contract moves with it —
  see `docs/city/city-json-v1.md` for the district definition.
