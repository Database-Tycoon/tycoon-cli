# v0.2.1

_Released: TBD_

Headline: **TBD**. Two streams in this one.

**Filesystem sources grow up.** Multiple named resources per source,
JSONL alongside CSV and Parquet, config that is validated instead of
quietly defaulted, and an interactive resource loop in `sources add`.
This is the first slice of the dlt-user archetype bet.

**The city stops being a static plan.** The simulation engine lands — a
radial layout that puts marts downtown and sources on the periphery,
streets only where demand exists, and the v4/v5 planners dissolved into
one resolved planner — and the three limitations that shipped alongside
0.2.0 are closed.

## Landed

_Filesystem-source entries (gh-222 through gh-228, PRs #229–#235) are
written in as they merge._

- **City simulation engine — radial layout, planner gaps, street
  thinning** (PR #206). Schemas are placed in rings by their longest
  chain depth over the cross-schema graph, inverted, so gold and mart
  precincts sit downtown and sources on the periphery; within a ring,
  ties break on fan-out, then member count, then name. A district is
  redefined as the schema's zoned precinct rect housing every member
  lot, which makes the orphan-exclusion failure mode impossible by
  construction rather than by check. Streets are generated where demand
  exists instead of everywhere, `town_network.py` closes three route
  completeness gaps, and the v4/v5 planners dissolve into a single
  resolved planner. Median route length on the dogfood catalog fell
  from 229 to 36 tiles.
- **Vehicles and guests are drawn.** 0.2.0 ticked both simulations and
  never called the layer draws, so the counters advanced while the
  street rendered empty. Both draw halves now run every frame,
  interpolated on the tick accumulator.
- **Coverage milestones are read.** The exporter's `achievements` block
  was emitted and never parsed, so a measured milestone displayed as
  `0% documented`. It is parsed now, and unknown coverage renders as
  unknown rather than as zero.
- **The renderer is CI-gated.** The vendored `tests/tycoon_city` suite —
  563 tests, including the `city.json` contract golden — joins the
  default pytest run instead of being ignored, and `src/tycoon_city`
  counts toward coverage (floor 68 → 73). A new `web` job runs `tsc`,
  the production build, a bundle-freshness check that the shipped
  `web_dist/` is exactly the build of `web/`, and the Playwright e2e
  suite. Before this, the CLI was gated and the renderer was not.

## Upgrading from 0.2.0

- **`tycoon.yml`'s `schema_version` stays at `2`** — there is no
  migration to run.
- **Filesystem sources sharing a schema now land in their own tables.**
  Projects with data already in the old generic `read_csv` /
  `read_parquet` table get a one-time warning naming both the stale
  table and the new one. New rows go to the new table only, so a dbt
  model still selecting the old name needs updating by hand.
- **The city looks different.** The radial layout reorders precincts by
  pipeline depth, so a city rendered from the same catalog will not
  match a 0.2.0 screenshot. The `city.json` contract moves with it —
  see `docs/city/city-json-v1.md` for the district definition.
