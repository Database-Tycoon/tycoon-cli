# v0.2.4 Release QA Report

**QA date:** 6 November 2026
**Release candidate:** `v0.2.4`
**Environment:** Windows, Python 3.12.13

## 1. Executive summary

The v0.2.4 package builds successfully, passes package validation, installs over v0.2.3, and passes CLI and dependency checks.

Core project operations, including filesystem ingestion, SQL querying, status reporting, history, and diagnostics, were exercised.

QA also identified Windows compatibility issues and service-level failures requiring engineering review.

**Overall assessment: QA execution completed; release sign-off pending review of outstanding findings.**

## 2. Passed checks

- Package build: wheel and source distribution.
- Twine validation of both distribution artifacts.
- CLI installation and version verification.
- CLI help and data command help.
- Project configuration and source registration.
- Filesystem ingestion and database schema inspection.
- Read-only SQL query against ingested data.
- Data status and history.
- Doctor diagnostics, with expected environment warnings.
- Rill project scaffolding.
- External command execution.
- Upgrade from v0.2.3 using the locally built v0.2.4 wheel.
- Dependency consistency check: 97 packages.
- Installed package metadata and Python compatibility metadata.

## 3. Outstanding findings

### QA-01 — Windows dbt file encoding

**Result: Failed**

Generated dbt SQL and YAML files contained Windows-1252 characters rather than UTF-8. dbt failed during parsing with a `UnicodeDecodeError`.

The generator uses `Path.write_text()` without explicitly specifying UTF-8 encoding. The issue was reproduced on Windows.

### QA-02 — Windows stop-command fallback

**Result: Failed**

When no PID file is available, the stop command falls back to invoking `lsof`. This executable was unavailable in the tested Windows environment, resulting in an unhandled `FileNotFoundError`.

### QA-03 — Rill service startup

**Result: Blocked by environment**

Rill project scaffolding succeeded, but service startup could not be verified because the Rill executable was not available on PATH.

### QA-04 — City catalogue endpoint

**Result: Failed**

The City frontend and JavaScript asset loaded successfully, but the catalogue endpoint returned HTTP 503. The underlying cause was not established.

### QA-05 — Credentialed end-to-end tests

**Result: Not run**

The credentialed E2E workflow was not executed because the required credentials and tokens were unavailable.

## 4. Additional observations

- Doctor detected the project configuration and dependencies. It warned that the project's local `.venv` was empty because QA used a separate isolated environment.
- The OSI semantic layer was absent. This is an optional feature.
- The v0.2.4 package was not yet published to the configured package index. Upgrade verification therefore used the locally built wheel.
- The missing `pip` module in the isolated upgrade environment did not prevent package metadata verification; Python's `importlib.metadata` was used instead.

## 5. Release recommendation

The package build, installation, core CLI checks, and local-wheel upgrade checks passed.

The Windows dbt encoding failure, Windows stop-command failure, and City catalogue HTTP 503 require engineering review. Rill startup and credentialed E2E coverage also remain unverified.

**Release approval should remain pending until the release owner reviews these findings and determines which must be resolved before publication and which can be accepted as documented limitations.**

No release tag or publication has been performed as part of this QA exercise.
